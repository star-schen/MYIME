# 输入与焦点策略（2026-10-05）

在“基础设置”中选择全局默认或 Windows 覆盖，修改“输入策略”后保存。应用配置的明确覆盖继续优先。本轮未运行实际输入验收。

## 跨应用组词

| 模式 | 离开原文本框时 | 返回原文本框时 |
|---|---|---|
| 暂存组词 retain（默认） | 隐藏候选，移除原文本框中 MYIME 拥有的组词文本，保留该上下文的引擎草稿和空锚点 | 原位置及选择区未被其他编辑改变时恢复草稿 |
| 取消组词 cancel | 清除原文本框的组词文本并取消引擎草稿 | 从空状态重新输入 |
| 提交当前候选 commit | 通过 Rime 提交当前组合，将结果写到原文本框 | 从空状态重新输入 |

暂存与新文本框各用自己的会话，不把应用 A 的草稿写进应用 B。TSF 锁未获得、原 composition 不再属于 MYIME、位置被编辑、文档关闭或缺少安全观察能力时，放弃恢复。保留记录限额约 32 个，不活跃记录超过五分钟释放；过期草稿不会继续恢复。应用自绘候选的协商保持有效。

写入原文本框由该 context 的异步 read/write edit session 完成。恢复必须等待自身清理的 OnEndEdit 结束，然后核对空锚点与选择区，防止快速来回切换引发重复恢复。当前活动文本写入失败时暂停输入，记录错误，不伪造成功 commit。

## Caps Lock

| 策略 | 组词期间按 Caps Lock | 大写字母与空格 |
|---|---|---|
| 候选内处理大写 compose_uppercase（默认） | 保留中文组合，后续大写作为字面文本追加到候选 | 空格或回车提交当前候选和大写文本；字母不参与拼音组词，Backspace 删除字母，Esc 取消 |
| 提交中文后直接大写 commit_then_direct | 将当前组合交给 Rime 提交，再让 Windows 切换大写锁定 | Caps 开启时空闲按键交给应用直接输入，空格遵从应用行为 |

Caps 键本身仍交给 Windows 更新系统开关。关闭 Caps 时若候选中有字面大写，先提交这段组合，避免它和随后的小写拼音混合。此策略针对中文模式；Rime 的 ascii_mode、Shift 中英文切换及 Ctrl/Alt/Win 快捷键边界保留。

配置值：

```toml
[default.input]
focus = "retain"
caps_lock = "compose_uppercase"
```

其他取值见上表。输入策略更新不会在活动草稿中途重建 Rime Provider；新学习分组也等当前组合结束后使用。

验收应覆盖 Notepad、浏览器及开始菜单，特别是已有中文草稿→Caps→字母→空格、失焦快速返回、移动选择区和关闭文档。步骤见 [本版验收](feature-acceptance.md)。
